# Handoff

## Goal

Sophisticated, learning, multi-game anti-cheat starting with CS2 (beat VACnet Live failure modes) and expandable past EAC-style single-channel designs.

Repo: https://github.com/p3nicillin/aegis

## How to run what exists

```bash
pip install -e ".[dev]"   # or: pip install -e . && pip install pytest
aegis train --sessions 48 --duration 75 --out models
aegis evaluate --model-dir models --stealth-curve
aegis simulate --aegis-capture --out data/sample_session
aegis ingest --model-dir models --capture-dir data/captures --port 9100
aegis serve --model-dir models
pytest -q
```

Artefacts land in `models/`: `ensemble.json`, `tabular.*`, `temporal.pt`, `novelty.pt`, calibrators, `conformal.npz`, `train_report.json`, `eval.json`, optional `dataset/`.

32. **Critical false-positive bug found and fixed**: `ModelBundle.prior` (session-level cheat rate) was being reused for the engagement-level LLR conversion, but `cal_temporal` is fit against the engagement-level rate — a different, empirically higher number (cheaters generate more engagements per session). This gave every engagement-level evidence unit a systematic positive bias with no cross-session discount to remove it, so SPRT accumulation eventually banned almost every *clean* identity too — measured at 93.3% false-ban within 20 simulated matches before the fix. Added `ModelBundle.eng_prior`, derived correctly from `cal.eng_y.mean()`; post-fix (measured through the actual `Adjudicator.decide()` path, not a raw-SPRT proxy — see below): 0% false-ban / 0% false-flag on clean identities, wallhack identities 100% flagged for review (median 7.5 matches) but 0% auto-banned in 20 matches. Full writeup and numbers in `COMPARISON.md`; fast regression test is `test_engagement_llr_not_systematically_positive_for_clean`. This was found doing the multi-session SPRT evaluation the system's own design was always supposed to be judged on — not a synthetic single-session metric.
33. Corrected the multi-session methodology itself after noticing it checked raw `sprt.crossed_ban()` instead of the real `Adjudicator.decide()` path, which also requires `min_engagements_for_ban` and conformal admission. The raw-proxy run had reported a 66.7% wallhack ban rate; the real policy path bans 0% in the same run (conformal correctly downgrades 10/15 raw-boundary crossings to REVIEW) while still flagging 100% for human review. The conformal gate is confirmed to be doing real protective work, not dead weight — `conformal_ever_blocked_a_raw_ban_cheat` in `multi_session_accumulation`'s report is the number to check going forward.
34. **Tested against real (non-synthetic, non-bot) human data for the first time, four escalating fix attempts, root cause fully understood, discrimination still unresolved** — a small public labelled dataset (2 real Steam accounts, one cheater-flagged, one legit, 33 real kill-window CSVs). Every real segment scored a saturated, non-discriminating `p_tabular`. Root-caused end-to-end across this session: (1) capability sparsity — fixed, confirmed on synthetic data (`sample_session_caps`/`capability_dropout`). (2) session duration (real clips are ~4.7s, training was always 45-90s) — fixed, confirmed on synthetic data (`sample_session_duration`). (3) **Placeholder-opponent artefact, conclusively ruled out**: rebuilt the real session with slot 1 populated by real tick data from 8 different other real accounts instead of zero ticks — the raw score was identical to 15 decimal places in every case, including the original placeholder. The opponent has zero effect; the issue is entirely in slot 0's own feature vector. (4) **Mechanism fully diagnosed**: independently rescaling each of the real session's 15 populated spectral feature values by 0.2x-3x left the raw score completely unchanged (`std == 0.0`) — the GBDT isn't reading these values for this exact NaN-pattern, it outputs a near-constant because too few training rows land in this exact combination to have learned real splits. Diagnosed further: capability and duration were sampled *independently*, making the joint "short clip + minimal capabilities" case (the real profile) ~2 of 64 training sessions; and `TabularGBDT.min_samples_leaf=40` is structurally above that. Fixed joint sampling (`sample_session_profile`) and retrained at 220 sessions instead of 64 — real, useful side effects (AUC 0.789→0.850 at one point, wallhack recall@review 0.0→1.0) but the real-data test still collapses, now to exactly two constants (0.948308, 0.942081) that don't correlate with the true label. **Mitigating context, not an excuse**: every real test session has zero valid engagements, and `min_engagements_for_ban=40` means `Adjudicator.decide()` cannot reach BAN for such a session regardless of the tabular score — measured `p_fused` (~0.62) lands at most in the low-severity "watch" band in the current architecture. That does not fix the underlying insensitivity, which would presumably also affect sessions with enough engagements to clear that gate (untested). Left open after four escalating, fully-diagnosed fix attempts — see `COMPARISON.md` for the complete investigation. Do not read `models/` as validated against real human behaviour; it is not.
35. **Fifth fix, mitigation not resolution**: the "untested" gap flagged in entry 34 (does the insensitivity also affect sessions with enough engagements to clear `min_engagements_for_ban`?) is now closed defensively rather than left open — added `coverage_shrink` (`aegis/models/ensemble.py`), a small pure function that shrinks `p_fused` toward the prior in proportion to how sparse the feature vector is, independent of engagement count, so a score built on ~11% real coverage can no longer move the posterior as if it were as trustworthy as one built on full coverage. Deliberately a no-op at and above 50% coverage (a fully-capable synthetic session routinely sits around 70% on its own; an earlier draft that shrank proportionally to raw coverage measurably dented a genuine aimbot session's score and was corrected). Verified: real sparse-data test's `p_fused` dropped from ~0.62 ("watch") to ~0.20-0.29 ("clear"); a full-capability aimbot session confirmed mathematically unaffected (`coverage_shrink(0.72) == 1.0`). This does not fix the GBDT's insensitivity (entry 34's layer-4 item is still open) — it stops the system from acting on an unreliable score as if it were reliable, which is a defensible thing to ship on its own. Fast regression test: `test_coverage_shrink_targets_extreme_sparsity_only`.
36. **Client attestation reference implementation** (`client/`) — a real, buildable C++ binary speaking `aegis/integrity/attest.py`'s challenge-response protocol end-to-end, not a stub. WinHTTP + BCrypt only (both native Windows, no third-party dependency); a minimal hand-written JSON encoder/extractor scoped to the known flat wire schema (`client/src/json_lite.*`, deliberately not a general parser). Two real probes: `module_hash` (genuine SHA-256 of the client's own executable) and `input_stack` (genuine `IsDebuggerPresent`/`CheckRemoteDebuggerPresent`). Verified live against a running `aegis serve`, both directions: a legitimate attestation returns `ok=1 attested=1`, and a deliberately wrong MAC sent by hand (bypassing the client entirely) is correctly rejected with `confirmed_tamper=True untrusted=True` — the security property was checked by attacking it, not just read from the code. `client/README.md` states plainly what this does not prove: no baseline registry exists to validate `module_hash` against (the client sends a real hash, nothing yet checks it against a known-good value), `input_stack`'s single probe is real but well-known and easily defeated, and the device key defaults to a lab-only shared secret (`SHA-256("aegis-dev-key")`, matching `Attestor`'s own fallback) pending real per-device provisioning.
37. **Sparse-session scoring policy (`sparse_session_policy`, `aegis/models/ensemble.py`) — closes entry 34's open item** via its option (b): a zero-engagement session no longer lets the tabular channel vote at all (its output on such NaN patterns was measured to be a near-constant), and the fused posterior is pinned within `SPARSE_ZERO_ENG_SHRINK=0.10` of the prior; engaged-but-<25%-coverage sessions also lose the tabular vote while engagement/temporal evidence keeps normal weight and `coverage_shrink` still scales the result. Full-capability sessions are provably untouched: `shrink == 1.0` and the tabular channel stays in (`test_full_capability_aimbot_still_scored_by_tabular` guards the entry-35 mistake class). Policy constants live in code, not `ensemble.json` — they are policy, not learned parameters. `Score.meta` now carries `coverage`/`tabular_used`/`shrink` for explainability.
38. **GBDT hyperparameter sweep tooling** (`lab/sweep_gbdt.py`, gitignored like the rest of `lab/`; results in `models/sweep_report.json`): 18-config grid on a fixed 256-session dataset; winner `min_samples_leaf=8, max_depth=6, lr=0.1` (AP 0.806→0.814 over old defaults). Note `min_samples_leaf=8` also directly attacks entry 34's structural sparsity mechanism (40 was above the ~2-row joint "short clip + minimal caps" cell). `train_ensemble`/`bootstrap_train` now accept `tabular_params` and record them in `train_report.json`.
39. **Simulator realism**: new `aim_smoothing` family (every humaniser knob at the plausible extreme simultaneously — FOV ≤6°, ≥16 smoothing ticks, ≥0.18 s delay, tremor retained, off-bone aim) so per-family recall is reported against a worst-case closet cheat; optional `net_jitter_ms` on `simulate_session` via bounded monotonicity-preserving random-walk tick-time jitter (`network_jitter_times`, default off); human skill sampling widened Beta(2.2,2.2)→Beta(1.8,1.8). All covered in `tests/test_scaling_loops.py`.
40. **Scale-up retrain against the harder simulator (384 sessions, tuned GBDT params)**: AUC 0.880→0.706–0.774, AP 0.757→0.568–0.654, ECE 0.103→~0.18–0.20 depending on eval draw. **This is not a regression in the detector — it is a harder measurement**: the old numbers were earned against an easier cheat distribution with suspiciously uniform humans, and are not comparable across simulator versions (per README's no-metric-spinning rule). Per-family recall@review on the new distribution: blatant 0.74, wallhack 0.52, adaptive 0.23, **aim_smoothing 0.25**, several single-symptom families near 0 in isolation — consistent with the long-standing finding that single-session recall understates the SPRT cross-match design.
41. **Per-family reporting fix (`train/dataset.py`)**: datasets now record each row's *family name* (`aim_smoothing`) rather than the collapsed behaviour label (`aimbot`) — previously the hardest closet profile was silently averaged into the mid-range aimbot bucket, making per-family recall flatter than reality. First eval with the fix is what produced entry 40's aim_smoothing-specific number.
42. **Verdict audit log** (backlog item 8): `integrity/audit.py` (`AuditLog` append-only JSONL, thread-safe), wired into both adjudication paths (`service/__init__.py` analyze route and `service/ingest.py::_score_session`), shadow verdicts included and flagged `shadow=true`; `PolicyConfig.audit_log_path` (empty disables); `aegis audit --tail N [--json]`. Every operator-visible decision is now reconstructible from what the system computed at the time.
43. **Per-title conformal gates** (backlog item 6): `FusionConfig.per_title_alpha[title]` overrides the global alpha for that title only; `Adjudicator.alpha_for(title)` resolves it, `decide(..., title=session.game)` uses it for conformal admission and names the source in the reason string (so a mis-typed looser-than-global override is visible in audits). Both call sites pass `session.game`.
44. **Signed model artefacts** (backlog item 8): `models/signing.py` HMAC-SHA256 over the deterministic artefact file set (`SIG.json`). Fail-closed wiring via `AEGIS_MODEL_KEY`: when set, `CalibratedEnsemble.save` signs automatically and `load` verifies before touching any artefact (tampered artefact or wrong key → `PermissionError`); unset → legacy friction-free behaviour. Deliberately symmetric crypto — this detects tampering by someone who had the machine; it does not pretend to solve key distribution.
45. **Review-label queue API** (backlog item 5, queue half): `POST /v1/reviews` appends one `ReviewLabel` row to the append-only store (`AegisConfig.review_store_path`, default `data/reviews.jsonl`); `POST /v1/reviews/refresh` runs `refresh_from_reviews` on demand and hot-swaps the serving ensemble, but **refuses with 409 below `MIN_LABELS_FOR_REFRESH=30`** rather than replacing bootstrap operating points with a fit on a handful of rows. Filing paperwork can never silently retrain the model as a side effect — refresh is a separate explicit call. Both routes sit behind the existing API-key gate; verified live (401 without key, rows land on disk parseable by `OnlineStore`, 422 on y∉{0,1} writes nothing). The review *UI* remains open.

## Next work (priority order)

1. **Real-data score collapse — root cause fully understood, needs real data or an architectural change to actually fix** (see entry 34 / `COMPARISON.md`). Confirmed not a test-harness artefact (real-opponent-data test ruled that out conclusively) and not fixable by further synthetic sampling tricks (capability dropout, duration variation, joint sampling, and a 3.4x larger training set all failed to give the GBDT real sensitivity in this exact NaN-pattern region — `min_samples_leaf=40` structurally limits how much a rare profile's sampling probability can help within a training set this size). ## Invariants — do not break

- Never zero-fill a missing capability.
- Never put trust/rank into the feature vector (prior only).
- Never auto-ban when conformal p ≥ α, even if posterior looks huge.
- Never ban from a single engagement; SPRT + `min_units_ban` + `min_engagements_for_ban`.
- Keep `FeatureSpec.digest` glued to every model artefact.
- Shadow mode on until an explicit operator decision.
- Any new calibrator gets its own prior derived from the population it was actually fit against (session-level vs engagement-level vs whatever a future per-title/per-channel calibrator uses) — never reuse another channel's prior for `prob_to_llr`. This is exactly how the false-ban bug in `COMPARISON.md`/entry 32 happened, and SPRT's cross-session accumulation has no mechanism to self-correct a bias that repeats identically every session.
